# Калибровка на «диких» играх (вне списка из 52)

Метод: для каждой игры — глубокое исследование из интернета (движок, релиз,
патчи, официальные требования, взвешенные плюсы/минусы решений), затем профиль
в DSS и сверка: железо и плюсы/минусы. Игры заведомо отсутствуют в разборах
`GAME_TECHANALYSES.md` и в примерах базы (проверено; сходство обязано идти
через обобщения, а не узнавание).

## Игра A. Helldivers 2 (2024, Arrowhead Game Studios)

- **Движок:** Autodesk Stingray (наследник Bitsquid), снят с поддержки в 2018.
  Тот же движок, что у первой Helldivers; смена по ходу разработки отвергнута.
- **Релиз ПК (08.02.2024):** серверный кризис (очереди, лимит одновременных
  игроков, падение сессий), затем скандал с обязательным PSN. Техника клиента —
  ровно для ниши; главный дефицит — серверы и сеть, не кадр.
- **Патчи/эволюция:** наращивание серверных мощностей, балансные патчи оружия,
  чистка шейдерного кэша после крупных патчей (рекомендация сообщества),
  FSR 3.1.5 → 4.0 по поколениям карт; DX11-режим для NVIDIA; CEO (03.2026):
  «недоинвестировали в движок», feature decay, раздутый размер файлов (100+ ГБ)
  — чистят постфактум.
- **Официальные требования:** мин i7-4790K / R5 1500X + 8 ГБ + GTX 1050 Ti /
  RX 470 (HDD); рек i7-9700K / R7 3700X + 16 ГБ + RTX 2060 / RX 6600 XT (SSD).
- **Технические пункты (проверено):**
  1. CPU-тяжёлая: процедурные карты + тотальная разрушаемость, мультиядро,
     AVX (тепловыделение выше обычного — нужен запас охлаждения).
  2. P2P-сессии до 4 игроков: хост = сервер (хуже FPS у хоста), клиент — легче;
     сложность масштабирует число врагов/размер карт → нагрузка CPU растёт.
  3. Async Compute включён по умолчанию, на современных CPU его советуют
     выключать; частицы (tessellation/shadows) — ручные твики конфига.
  4. VRAM spillover: переполнение видеопамяти → просадки (смотреть лимит).
  5. Апскейлы FSR/DLSS/XeSS; HDR; Linux/Proton и Fullscreen-нюансы.
- **Взвешенные плюсы/минусы решений:**
  - `+` Свой старый движок: команда знает его наизусть, ноль цены переезда.
  - `+` P2P без выделенных серверов: дёшево на старте.
  - `−` Мёртвый движок: каждый новый API/фикс — ручная работа (признано CEO).
  - `−` P2P: хост платит FPS, нет серверного арбитра (читы/стабильность).
  - `−` Серверная ёмкость не спроектирована под взрыв онлайна.
- **Профиль DSS:** 3D / procedural / large / prototype / custom / pc_windows,
  1080p / high / 60, object medium, npc high, multiplayer true, players 4,
  функции: physics_simulation, particle_systems, procedural_vegetation,
  character_animation, dynamic_shadows, post_processing, multiplayer_netcode.
- **Ожидание от инструмента:** GPU класс 2 (RTX 2060 — рек), CPU класс 3
  (3700X); сетевые методы в выдаче для P2P-коопа; предупреждение про нагрузку
  хоста — ? (проверить: такого риска в движке может не быть — зафиксировать
  как пробел/ограничение, а не баг).
- **Результат зонда (факты, пустая корзина):** GPU 0.487 класс 3 (референс
  RTX 4060 — запись в каталоге проверена), CPU 0.676 класс 4 (референс
  i7-13700K). CPU связывает сильнее GPU (0.68 > 0.49) — направление «CPU-тяжёлая
  игра» инструмент определил верно. Топ: contact shadows, particle_pooling,
  patch pipeline, depth prepass, upscaling #9, DRS #8. Сеть: delta_compression
  #23 conditional, dedicated_server #31 conditional, relevancy #42. Риски: пусто
  (сессия 4 игрока < порога 16 для `network_scale` — по правилам верно).
  Похожие: максимум Factorio 0.719 — близкого аналога в базе нет, и инструмент
  это честно показывает низкими оценками, а не натягивает.
- **Вердикт:**
  - GPU класс 3 против официальных RTX 2060: цели официалов (FPS/качество)
    не указаны — вердикт НЕ ВЫНЕСЕН (ни совпадение, ни промах). Зафиксировано.
  - CPU класс 4 против 9700K/3700X: та же причина — цели неизвестны; при этом
    направление (CPU связывает) совпало с реальностью (AVX, хост-нагрузка).
    НЕ ВЫНЕСЕН как промах, отмечено наблюдение.
  - Предупреждения про хост-налог P2P в движке НЕТ (проверен весь список рисков
    в `recommender.detect_risks`; в анкете нет поля топологии — только
    `multiplayer` + `player_count`). Это задокументированное ограничение, не баг:
    добавлено пулей в README §11. Сетевые методы под серверную модель при P2P
    выдаются как conditional — приемлемо, но без пометки про P2P.

## Игра B. Hogwarts Legacy (2023, Avalanche Software / Portkey)

- **Движок:** Unreal Engine 4 (кастом Avalanche).
- **Релиз ПК (02.2023):** без серверных драм; техника: traversal-статтеры у всех,
  прожорливость VRAM/RAM, слабый RT без твиков, DX12 оверхед драйвера NVIDIA.
  Шейдерных статтеров нет — предкомпиляция при первом запуске.
- **Патчи:** RT-твики сообщества, DLSS 3 как must-have, драйверы; суть не
  менялась: RT остался опцией «для 4090», traversal-статтеры — налогом движка.
- **Официальные требования:** мин i5-6600 / R5 1400 + 16 ГБ + GTX 960 4 ГБ
  (720p/30 low, HDD); рек i7-8700 / R5 3600 + 16 ГБ + GTX 1080 Ti / RX 5700 XT /
  Arc A770 (1080p/60 high, SSD); ультра: i7-10700K / R7 5800X + 2080 Ti (1440p)
  / 7900 XT (4K); за 1080p — 32 ГБ RAM рекомендовано.
- **Технические пункты (проверено):**
  1. CPU скромный: даулкор тянет 1080p/Ultra без RT; польза максимум от 6 ядер,
     HT не помогает и не вредит.
  2. RT (отражения/тени/AO): без твиков хуже/равно растру (RTAO хуже SSAO,
     поп-ин RT-теней); вкл RT режет FPS вдвое даже на 4090.
  3. DLSS 3 Quality: 4K/Ultra/RT Ultra 100+ FPS, входной лаг не чувствуется.
  4. VRAM: 4K RT — до 13–15 ГБ; без RT — ~8 ГБ; <12 ГБ → снижать текстуры.
  5. RAM: 16 ГБ хватает (пик ~14 ГБ в 4K max RT у DSOG); 32 ГБ — страховка.
- **Взвешенные плюсы/минусы решений:**
  - `+` Предкомпиляция шейдеров: целый класс статтеров убит до старта.
  - `+` RT как опция с дефолтом «выкл»: слабое железо не страдает.
  - `+` Зернистые RT-тоглы (3 штуки + качество) вместо одного рубильника.
  - `−` Traversal-стриминг не дотянут: статтеры у всех конфигураций.
  - `−` RT без твиков — ловушка (хуже растра за полцены FPS).
  - `−` Ультра-текстуры без VRAM-защиты: 8–10 ГБ карты хлынут в своп.
- **Профиль DSS:** 3D / open_world / large / prototype / unreal / pc_windows,
  1080p / high / 60, object high, npc medium, функции: open_world_streaming,
  large_scale_terrain, character_animation, ai_pathfinding, dynamic_shadows,
  post_processing, physics_simulation.
- **Ожидание от инструмента:** GPU класс 3 (1080 Ti — рек), CPU класс 2–3
  (8700/3600); `pso_precaching_warmup` высоко (предкомпиляция — их победа).
  Про RT сравнение НЕ тестируется этим профилем (функция GI не выбрана —
  RT-методы не кандидаты; отдельный RT-тест уже пройден ранее: quality-приоритет
  поднимает RT GI на #4).
- **Результат зонда (факты, пустая корзина):** GPU 0.477 класс 3 (референс
  RTX 4060), CPU 0.653 класс 4 (референс i9-12900K), VRAM 5.6, RAM 11.9.
  `pso_precaching_warmup` — #32 lower_priority (score 0.55; данные: cost 3,
  cx 3, gain 0.45, late high). Похожие: Horizon 0.876, GoT 0.851, W3 0.848,
  DD2 0.846 (новый пример работает). Риски: пусто (стадия prototype —
  по правилам рано).
- **Вердикт:**
  - GPU класс 3 = классу официальных 1080 Ti. СОВПАДЕНИЕ (уровень классов).
  - CPU класс 4 против официальных класса 3 и реальности «даулкор тянет»:
    ЗАВЫШЕНИЕ НА КЛАСС. Причина известна из кода: пустая корзина = допущение
    «код не оптимизирован», формула не видит качество threading (на входе его
    нет — измерить нечем). Чинить формулой нельзя: любая поправка была бы
    подгонкой под один анекдот и сломала бы якоря. Зафиксировано как известное
    ограничение оценки без корзины.
  - `pso_precaching_warmup` #32: lower_priority означает «дешёвые победы
    раньше», а не «не делать». Механизм (cost/cx/gain) — данные, не баг.
    Отмечено как наблюдение: флаг может недодавать вес обязательной гигиене
    DX12, но доказательств для смены данных нет — НЕ МЕНЯЮ.
  - VRAM 5.6 против измеренных ~8 ГБ (1080p high без RT): НИЖНЯЯ ГРАНИЦА.
    Формула общая, HL — VRAM-прожорлива (ультра-текстуры). Наблюдение без правки;
    покрыто оговоркой «ориентировочно».

## Игра C. Remnant 2 (2023, Gunfire Games)

- **Движок:** Unreal Engine 5 (переход поздно, поэтому не афишировался);
  Nanite — да, Lumen на старте — нет, аппаратного RT — нет.
- **Релиз ПК (07.2023):** технически приемлемо, но: натив 1080p/Ultra/60 тянут
  только 6900 XT / 7900 XTX / 4090; 3080 — середина 50-х. Разработчик честно:
  «игра спроектирована под апскейл» (DLSS/FSR2/XeSS обязательны), тени — главный
  рычаг кроме апскейла. DLSS 3 (FG) ждали как обязательное добавление.
- **Патчи:** перф-апдейты после релиза; Lumen — «возможно позже»; консоли
  рендерят изнутри ~794p (апскейл как архитектура, а не костыль).
- **Официальные требования:** мин i5-7600 / R5 2600 + 16 ГБ + GTX 1650 /
  RX 590; рек i5-10600K / R5 3600 + 16 ГБ + RTX 2060 / RX 5700.
- **Технические пункты (проверено):**
  1. GPU-тяжёлая при скромном CPU: даулкор даёт 80+ FPS (1080p/DLSS Perf/Ultra);
     Nanite разгружает CPU и убивает traversal-статтеры (на Low без Nanite
     статтеры возвращаются — инверсия-пруф).
  2. Официальные требования подразумевают включённый апскейл (иначе 2060
     не тянет даже 1080p/Ultra/60).
  3. Кооп до 3 игроков; хаб Ward 13 (толпа NPC) — CPU-точка для тестов.
  4. Тени — второй рычаг после апскейла.
- **Взвешенные плюсы/минусы решений:**
  - `+` Nanite: нет поп-ина геометрии + нет traversal-статтеров + ниже нагрузка CPU.
  - `+` Честность про апскейл как системное требование (а не сюрприз).
  - `−` Требования вводят в заблуждение без пометки «с апскейлом».
  - `−` Натив-разрешение фактически не поддерживается как таковое.
  - `−` Lumen вырезан ради FPS (свет проще, чем мог быть).
- **Профиль DSS:** 3D / procedural / large / prototype / unreal / pc_windows,
  1080p / high / 60, object high, npc medium, multiplayer true, players 3,
  функции: large_scale_terrain, character_animation, ai_pathfinding,
  dynamic_shadows, particle_systems, post_processing, multiplayer_netcode.
- **Ожидание от инструмента:** пустая корзина — класс 3–4 (честный натив);
  корзина с `temporal_upscaling` — класс 2 (офиц. 2060); `virtual_geometry_clusters`
  (Nanite) высоко; traversal-риск покрыт. Это ключевой тест петли
  «корзина → пересчёт».
- **Результат зонда (факты):** пустая корзина — GPU 0.484 класс 3 (RTX 4060).
  С корзиной [upscaling, DRS, streaming, HLOD, pooling, PSO-warmup] — GPU 0.310
  класс 2 = уровень официальных RTX 2060. Механизм проверен по строкам базы:
  `temporal_upscaling` imp_gpu=-2, `dynamic_resolution_scaling` imp_gpu=-2,
  `hierarchical_lod` imp_gpu=-2 → множитель 1+0.06×(−6)=0.64;
  0.4837×0.64=0.3096 — арифметика сошлась копейка в копейку. CPU не изменился
  (0.6677): сумма imp_cpu корзины = +1−1−1+0+0+1 = 0 — тоже проверено, не угадано.
  Официальные требования подразумевают включённый апскейл (заявление dev),
  корзина делает его явным — инструмент воспроизвёл не цифру, а УСЛОВИЕ.
  `virtual_geometry_clusters` — #44 lower_priority/late_difficult/needs_prototyping
  (данные: stage preproduction, late critical, cost/cx 5, conf 0.65).
  Похожие: Borderlands 3 0.772 топ-1 — apt (UE кооп-шутер), оценки умеренные, честные.
- **Вердикт:**
  - Петля «корзина → пересчёт» на официальном кейсе: СОВПАДЕНИЕ С МЕХАНИЗМОМ.
    Сильнейшее подтверждение калибровки за сессию.
  - Абсолют пустой корзины (класс 3) против натив-реальности (класс 4+ на Ultra):
    цели не совпадают (профиль high/60, реальность Ultra) — ВЕРДИКТ НЕ ВЫНЕСЕН.
  - Nanite #44: данные говорят «архитектурная ставка предпродакшна, дорого,
    рискованно» — Gunfire сменил движок поздно и всё равно вывез, но это
    исключение уровня исполнения, а не норма. Данных для смены stage/late_cost
    нет — НЕ МЕНЯЮ, отмечено как наблюдение.
