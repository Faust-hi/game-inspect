# Анализ партий 1–11 в контексте game-inspect

Дата проверки: 7 сентября 2026. Реализации и исправлений приложения не выполнялось. Исследования для будущего отдельно сохранены в `docs/future-performance-research.md` со статусом «не реализовывать в текущей задаче».

## Основной результат

Партии полезны как черновая подборка инженерных кейсов, но **не готовы быть эталонной базой для расчёта требований к железу**. Они смешивают версии игр, платформы, настройки, методы реализации, игровые механики, маркетинг и неподтверждённые причинные объяснения. Часть ошибок непосредственно меняла бы подбор GPU/CPU, если использовать эти сведения для калибровки.

Это дефекты справочного материала. Прямое влияние именно этих Markdown-файлов на работающий расчёт не установлено: загрузчик их не читает. Отсутствие интеграции новых полей/методов — пробел, а не уже существующий runtime-баг. Отдельные перечисленные игры и общие методы уже представлены в seed; это не означает, что содержание партий туда перенесено.

Проверка охватила структуру всех 11 документов, 58 игровых разделов и 980 строк таблиц «Инженерные решения». Выполнены точное сопоставление кодов, проверка схемы, поиск противоречий, адресная проверка наиболее значимых утверждений по первичным источникам. **Не каждое историческое утверждение из 980 строк независимо подтверждено**: непроверенные утверждения ниже прямо отделены от опровергнутых. Отсутствие замечания к конкретной строке не означает её верификации.

Файлы доказательств: `inventory.json` (строки, коды, источники, SHA-256, результаты проб), `COVERAGE.md` (все 58 профилей), `inspect_batches.py` (повторяемая структурная проверка). Контрольные 91 файл первого аудита не изменились.

## Как партии связаны с приложением

1. `backend/app/config.py:12` задаёт DATA_DIR внутри `backend/app/seed/data`. `_example_files` в `seeder.py:38` читает `game_examples.json`, `track1/*.json`, `track2/*.json`. Партии из корня и `DSS-анализ-железо.md` в этот путь не входят. Их текст не участвует в hardware/rules/TOPSIS.
2. В 980 строках найдено 973 различных обозначения методов. Только 19 строк, содержащие 15 различных кодов, точно совпадают с действующим каталогом. Все совпадения находятся в партии 1. **Это не означает 1.94% смыслового покрытия:** например, `megatexture_virtual_texturing` может соответствовать существующему `virtual_texturing`; требуется ручная проверка смысла.
3. Точные совпадения названий ряда игр уже есть в seed: Portal/Portal 2/HL2/CS:S — Track 1, AC Unity/GTA V/DOOM Eternal/Metro/Cyberpunk — legacy; Elden Ring/Alan Wake 2/RDR2 — Track 2 draft. Инвентарь показывает исходные файлы и статусы, не состояние персональной БД и не все возможные совпадения по алиасам.
4. `GameExample` (`models/entities.py:235`) не имеет полей `api_versions`, `min_hw`, `rec_hw`, `frame_budget`, `streaming_io`, `engine_limits`, `antipiracy` и ряда остальных паспортных полей. Проверка `_coerce(GameExample, паспорт)` сохранила только `title`: остальные переданные поля отсутствуют среди столбцов. Просто преобразовать Markdown в JSON недостаточно для сохранения нового паспорта через текущий импорт.
5. Значения `3D voxel`, `infinite procedural`, `infinite`, `very_high`, `PC`, `macOS` не соответствуют текущим перечислениям. Это подтверждено `publication.enum_problems`. Человек понимает текст, но поля перед импортом требуют осмысленной нормализации. Нельзя автоматически превращать infinite в very_large без обозначения потери смысла.
6. У GameExample уникален title, а профиль версии/рендера не является отдельной сущностью. Оригинал/ремастер/Enhanced, DX11/DX12, native/upscaled и FG/base FPS нельзя без потерь свести к одной строке требований.
7. Во всех 11 файлах — ноль URL с явной схемой http(s). Есть названия сайтов, статьи, голые домены и ссылки словами; это **не отсутствие любых источников**, но отсутствует проверяемая цепочка «утверждение → точная страница/слайд → версия/дата». Метки ✅ и verified_by сами по себе такой цепочкой не являются.

## Партия 1 — Portal, Portal 2, GMod, CoD, Civ V, Witcher 2, Oblivion, Batman, FFXIV

**Полезная часть.** Наиболее близкий к текущей онтологии документ: встречаются `physics_lod_sleeping`, `particle_pooling`, `time_sliced_pathfinding`, `hierarchical_lod`, `animation_lod_budget`, `headless_dedicated_server`. Это кандидаты на источники/примеры для существующих карточек, не обязательно новые методы.

**Подтверждённые несостыковки:**

- Строки 19 и 53 несовместимы: в одном месте Portal RTX допускает RTX 3060, в другом требует RTX 40. NVIDIA на старте прямо описывала игру на RTX 3060/3080 с DLSS 2; 40-я серия нужна для указанного сценария DLSS 3/4K, не для самого запуска. [NVIDIA, Portal with RTX](https://www.nvidia.com/en-us/geforce/news/gfecnt/202212/portal-rtx-available-december-8/).
- В одном паспорте Portal объединены оригинал DX8/9, Linux, RTX Remix и современные требования. Якорь оригинала не может проверять оценку path tracing.
- Строка 35 относит SSE к GPU. Это неверное расположение CPU-требования в структуре паспорта; из него нельзя строить GPU-фильтр.
- `hierarchical_lod` в строке 346 описан просто как несколько LOD. Совпавшее имя ещё не доказывает применение именно иерархических кластерных прокси, а не обычного LOD отдельных объектов.

**Не подтверждено:** SDF для гелей Portal 2, точное удвоение lightmap-памяти, повсеместный forward+, универсальный конфликт stencil-порталов с водой и линейная цена портального аудио. Для этого нужны конкретные доклады/реализации; имя игры и общая страница VDC недостаточны.

**Значение для проекта.** Сохранить контекст и ограничения потенциально полезно. Переносить строку `headless_dedicated_server` как снижение требований клиентского ПК нельзя: это повторило бы D04 первого аудита. Для каждой записи нужны сторона client/server, стадия offline/runtime и версия.

## Партия 2 — семейство Source

**Полезная часть.** Ветки движка, draw-call submission, упаковка ресурсов, сетевой тик и миграции API дают хорошие темы для объяснения компромиссов.

**Подтверждённые несостыковки:**

- Строка 46: «33.3 мс (60 fps цель)». Арифметически 60 FPS соответствует примерно 16.67 мс, а 33.3 мс — 30 FPS. Ошибка вдвое непосредственно портит frame-budget калибровку.
- Строка 14 присваивает HL2: Deathmatch AppID 220; у отдельной игры AppID **320**. [Страница Valve в Steam](https://store.steampowered.com/app/320/STEAM?l=english).
- Имя `fixed_timestep_physics_60hz` сопровождается числом 66.6 Гц (строка 26). Уже внутри записи не определено, что является параметром; render FPS, physics tick и network tick должны быть раздельны.
- 103 локальных кода не совпадают с кодами Method. Это не 103 отсутствующих функции: часть описывает сцену, распространение игры, озвучку и сюжетную организацию.

**Не подтверждено:** navmesh вместо waypoint/node graph именно для NPC HL2; универсальный MAX_MAP_ENTITIES=2048 для всех перечисленных веток и видов сущностей; детали патчей 2025/2026 и новый legacy AppID без точных официальных ссылок. Отметка «VDC заблокирован, взято через Wikipedia» — ограничение проверки, а не подтверждение.

**Значение для проекта.** Подходящие существующие карточки — `fixed_timestep_physics`, `physics_lod_sleeping`, `tickrate_budgeting`, `async_loading_pipeline`; конкретные соответствия нужно установить отдельно. VPK-упаковка, shader warmup и string-table cache — разные механизмы, их нельзя объединять в одну гарантированную скидку загрузки.

## Партия 3 — FromSoftware

**Полезная часть.** Различие render FPS и шага симуляции, история оригиналов/ремастеров, ограничения показа и незакрытые шейдерные задержки — релевантные классы рисков.

**Подтверждённые внутренние проблемы:**

- DS3: строка 151 содержит 8.3 мс для PS4 Pro, а строка 153 — cap 60. 8.3 мс означает около 120 FPS. Sekiro повторяет 8.3 мс (строка 205) при заявленной цели 60 FPS выше. Это не согласованный набор измерений; 120 FPS на соответствующих консольных версиях в этой проверке не подтверждены.
- Заголовки Remastered/SotFS объединены с минимальными требованиями оригинала. Автоматическое обучение на такой строке связывает нагрузку одной версии с оборудованием другой.
- Значительная часть «методов» — posture, resurrection, setting, отсутствие создания персонажа. Это игровые решения, но величина CPU/GPU-эффекта из них не следует.

**Не подтверждено:** «EAC запрещает фоновую компиляцию DX12» (строка 412) и производный `eac_blocks_async_shader_compile`. Наличие античита и shader stutter не доказывает такую причинность. Также отсутствие импорта видимой DLL само по себе недостаточно для универсального доказательства отсутствия защиты во всех версиях.

**Значение для проекта.** Подходят темы `fixed_timestep_physics` и `pso_precaching_warmup`, но не правило «EAC ⇒ warmup невозможен» и не правило «все FromSoftware ограничены одинаковой физикой». Не надо добавлять DRM-флаги как коэффициенты железа без измерения конкретного пути.

## Партия 4 — Assassin’s Creed / For Honor

**Полезная часть.** Толпа, анимации, подача геометрии, переход сетевой архитектуры и стоимость стриминга действительно важны для анкеты.

**Подтверждённые ошибки:**

- В AC Unity минимум GPU — GTX 660/R9 270X, CPU AMD — FX-6350 (строка 40). В опубликованной спецификации Ubisoft указаны GTX 680/HD 7970 и FX-8350; рекомендованный Intel — i7-3770, а не i7-4790 из партии. [Ubisoft, требования Unity](https://store.ubisoft.com/uk/assassins-creed-unity/56c4947a88a7e300458b45d6.html), [руководство NVIDIA времени релиза](https://www.nvidia.com/en-us/geforce/news/assassins-creed-unity-graphics-and-performance-guide/).
- Unity сначала получает 30 FPS (строка 42), затем Origins сравнивается с «60 FPS как Unity» (строка 100). Сводка снова считает Unity 30 FPS. Сценарий не определён.
- For Honor назван AC-тайтлом (строка 284): общее семейство движка не делает игру частью Assassin’s Creed.

**Не подтверждено:** 30 000 одновременно полноценно симулируемых NPC, причинная цепочка «50 000 draw calls ⇒ паралич DX11», «Denuvo+VMProtect ⇒ 100% CPU», наличие RT в Valhalla для перечисленных версий. Эти сведения требуют первичного доклада или контролируемого замера. Число строк кода не измеряет стоимость кадра.

**Значение для проекта.** Уместны `ecs_data_oriented_crowd`, `crowd_instancing_impostors`, `agent_update_budget`, `gpu_compute_culling`, `network_relevancy_priority`. Но число персонажей во всём городе нужно отделять от видимых, активных и полноценно обновляемых. Присвоение единого npc_count=30000 закрепит ошибочную нагрузочную модель.

## Партия 5 — Bethesda / Creation

**Полезная часть.** Precombines/previs, ограничения адресного пространства, сохранения, открытые миры и миграция в multiplayer заслуживают отдельных паспортов.

**Подтверждённые несостыковки:**

- Строка 126 приписывает Fallout 4 32-bit. Официальные требования прямо указывают 64-bit processor/OS; также в партии неверны AMD CPU/GPU минимума: на Steam — Phenom II X4 945 и HD 7870, в партии — FX-6300 и HD 7770. [Fallout 4, требования издателя в Steam](https://store.steampowered.com/app/377160/fallout-4/?l=english). Для утверждения о конкретном формате executable при отдельной технической проверке следует проверять бинарник/документацию, а не выводить его только из ОС.
- Starfield: минимум Ryzen 5 1600 и рекомендованные i5-12400/Ryzen 5 5600X не соответствуют опубликованным перед релизом 2600X и i5-10600K/3600X. [Bethesda, спецификация от 24.08.2023](https://bethesda.net/en-US/news/starfield-launch-details-pc-specs-and-more).
- «Starfield 32-bit до патча 2024» (строка 272) не имеет подтверждающего источника; переносить на него ограничения оригинального Skyrim недопустимо.

**Не подтверждено:** универсальный точный лимит 3.1 GB, обязательная скорость SSD 500+ MB/s, фиксированные 15 FPS в Бостоне при отключении precombines, причинная трактовка отсутствия человеческих NPC в Fallout 76 как невозможности сетевого протокола. Здесь смешаны адресное пространство процесса, физическая RAM, размер сейва, полоса I/O и инженерные/дизайнерские решения.

**Значение для проекта.** Полезны `baked_occlusion_culling`, `hierarchical_lod`, `snapshot_slot_saves`, `async_incremental_saves`, `world_partition_streaming`. Но prebaked visibility и объединение геометрии — разные вещи. Исторический баг конкретной версии не должен становиться постоянным штрафом всем Creation-проектам.

## Партия 6 — Rockstar

**Полезная часть.** Геометрия/стриминг больших миров, VRAM-детекция, варианты API и различия Legacy/Enhanced хорошо показывают необходимость версионных профилей.

**Подтверждённые несостыковки:**

- GTAV помечает аппаратные требования «PC, 2013» (строки 108–109). PC-версия вышла **14.04.2015**; 2013 относится к первоначальному консольному релизу. [Rockstar, объявление PC-релиза](https://www.rockstargames.com/newswire/article/25o2411812a31k/grand-theft-auto-v-is-now-available-for-pc).
- Заголовок 2013/2022, требования PC 2013, отдельные 4K-конфигурации и Enhanced 2025 сведены в один профиль. Сведения про 4K не содержат достаточного протокола настройки/версии/сцены и статуса измерения.
- PS3 в строке 114 описана как «512 MB RAM», тогда как сводка строки 277 использует 256 MB RAM. Это смешение общего объёма разных пулов и системной RAM, непригодное для единого memory_model.
- Число «1.5 года» для переноса RDR2 (строки 187/189/196) не согласуется с указанными в карточке датами 26.10.2018 → 05.11.2019: это примерно год. В сводке самого документа (строка 312) также указан год. Для аппаратного вывода сама длительность разработки не является измерением производительности.

**Не подтверждено:** точная причина высокочастотного порога 160–180 FPS, обобщённое «Vulkan всегда лучше, DX12 только fallback», причинность VRAM-overflow и конкретный рецепт запуска для всех патчей. Такие сведения полезны как версия-зависимые проблемы совместимости, но не как глобальные коэффициенты API.

**Значение для проекта.** `terrain_clipmap`, `virtual_texturing`, `world_partition_streaming`, `async_loading_pipeline`, `quality_tier_scalability` могут получить контекст. Нельзя выводить универсальный CPU-выигрыш Vulkan только из сравнения одного RDR2-патча/драйвера.

## Партия 7 — id Tech

**Полезная часть.** Virtual texturing, бюджет страниц за кадр, GPU очереди, графический API и отличие времени подготовки от runtime.

**Подтверждённые ошибки:**

- RAGE назван Games for Windows Live (строка 188). Bethesda прямо указывает Steamworks. Там же опубликованы другие рекомендованные GPU, чем GTX 260/HD 4870 из партии. [Bethesda Support, RAGE](https://help.bethesda.net/app/answers/detail/a_id/31922/~/what-are-the-system-requirements-for-rage%3F).
- «Инженерные методы» содержат `doomguy_slayer_named_in_dlc2`, `breaking_bad_viral_marketing`, коллекционные предметы и сюжет. В них нет определённой аппаратной работы. Число таких строк не является числом аппаратных технологий.
- Switch-релиз DOOM указан как 10.11.2017 в платформах и 11.10.2017 в патчах (строки 13/66). Уже внутри документа дата неоднозначна.
- Цены многих методов сведены к «дороже», «удорожание» без ресурса, условий и масштаба. Это не пригодная величина для impact_* или performance_gain.

**Не подтверждено:** цель RAGE 30 FPS для всех указанных платформ, диапазон +30–66% от Vulkan вне конкретных GPU/сцен, универсальный физический смысл vt_maxPPF как «аппаратного декодирования». Нужен раздельный учёт page budget, декомпрессии, загрузки и кадра. Историческое «первый в индустрии» не добавляет предсказательной ценности.

**Значение для проекта.** `virtual_texturing`, `async_loading_pipeline`, `tiled_clustered_light_culling`, `bindless_uber_shaders` — кандидаты на смысловое сопоставление. Наличие послойного разрушения демона не доказывает применение `destruction_geometry_cache`: процедурное повреждение и заранее записанный кэш — разные реализации.

## Партия 8 — Crytek

**Полезная часть.** Хороший набор контрастов: CPU-геометрия, тесселяция, software GI, переход API, звук и разные версии движка.

**Подтверждённые ошибки и противоречия:**

- Crysis 3 допускает GeForce 9800 GT/HD 3870 и пометку «только DX9?» (строка 192), а хвост документа подтверждает обязательный DX11. EA действительно требует DX11 и указывает минимум GTS 450/HD 5770. [EA, Crysis 3](https://www.ea.com/games/crysis/crysis-3).
- В Hunt переход на CRYENGINE 5.11 и новые консоли **подтверждается** официальным объявлением 15.08.2024. [Crytek](https://press.crytek.com/a-new-era-begins-today-with-hunt-showdown-1896-out-now-on-pc-playstation-5-and-xbox-series-xs).
- Из этого объявления не следует аппаратный RT, а партия вводит `ray_tracing_2024` и отдельные RT-требования. Crytek описывает Total Illumination/SVOGI с использованием ray tracing и для старого Hunt; наличие трассировки не тождественно обязательным RT-ядрам. [Техническое объяснение Crytek](https://www.cryengine.com/news/view/how-we-made-neon-noir-ray-traced-reflections-in-cryengine-and-more), [SVOGI](https://www.cryengine.com/docs/static/engines/cryengine-5/categories/23756816/pages/25535599).

**Не подтверждено:** мотив проектирования Crysis строго под 6–8 GHz, «неустранимое» CPU-ограничение, обязательный hardware RT именно Hunt 1896, обобщённые crossplay и жанровые первенства. Доклад или наличие CPU-bottleneck не доказывает все эти причинные объяснения.

**Значение для проекта.** Здесь особенно важно разделить `voxel_cone_tracing`/SDF/GI и `hardware_raytraced_gi`. Автоматическое соответствие слова ray_tracing аппаратному RT исключит совместимые карты и завысит требования. Для аудио полезен отдельный паспорт фактической реализации, а не общий GPU-штраф.

## Партия 9 — Frostbite

**Полезная часть.** Сеть, 64/128 игроков, разрушения, RT-отражения и раздельные этапы появления API/апскейлинга.

**Подтверждённые несостыковки:**

- Строка 431 объединяет коммерческое появление DXR и DLSS в BFV в ноябре 2018. NVIDIA сообщает о добавлении DLSS в обновлении **февраля 2019**. [Объявление NVIDIA от 13.02.2019](https://www.nvidia.com/en-us/geforce/news/battlefield-v-metro-exodus-ray-tracing-dlss/).
- Строка 120 задаёт «Rec HW (PS4 Pro 4K)» через i7/Ryzen/GTX/Vega — это ПК-конфигурация под консольным заголовком. Нельзя использовать её как измеренный аппаратный профиль PS4 Pro.
- BFV «RT+DLSS» допускает RX 6800 XT (строка 191), тогда как цитируемое введение DLSS относится к GeForce RTX. Нужны разные режимы/технологии для разных производителей, а не один общий слот.
- Одинаковые CPU/GPU-комбинации повторяются между несколькими играми без отдельных источников и протоколов. Само повторение не доказывает ложность, но не создаёт независимые эталоны.

**Не подтверждено:** точный смысл 10/30 Hz при релизе BF4; перенос physics tick на сетевую доставку; отрицательные последствия конкретного DRM; список государств/штатов с «запретом лутбоксов». Юридические утверждения не проверялись здесь и не должны попадать в аппаратную модель. Наличие API также не доказывает отсутствие CPU-overhead.

**Значение для проекта.** Связать можно с `network_relevancy_priority`, `delta_compression_state`, `client_prediction_reconciliation`, `tickrate_budgeting`, `destruction_geometry_cache` после проверки конкретной реализации. Частоты симуляции сервера, отправки пакетов и отображения клиента надо различать. Схема «128 игроков = удвоить всю нагрузку ПК» из партий не следует.

## Партия 10 — Metro, Deus Ex, Kingdom Come, Alan Wake 2

**Полезная часть.** Очень сильные потенциальные кейсы для API/feature compatibility, software/hardware GI, апскейлинга и версий fallback-рендера.

**Подтверждённые ошибки:**

- Metro Enhanced рекомендует GTX 1070/RX Vega 56 для 4K (строка 59), одновременно объявляя RT-оборудование обязательным. 4A действительно требует RT-capable GPU и выделяет Enhanced в отдельный продукт. [Анонс 4A](https://www.4a-games.com.mt/4a-dna/2021/2/3/deep-silver-and-4a-games-announce-metro-exodus-pc-enhanced-edition-and-reveal-more-details-for-playstation-5-and-xbox-series-xs-upgrade).
- Дата Enhanced 14.06.2021 неверна для PC: разработчик опубликовал релизный технический разбор **6 мая 2021**, отдельно указав консольный выход 18 июня. [Технический разбор 4A](https://www.4a-games.com.mt/4a-dna/in-depth-technical-dive-into-metro-exodus-pc-enhanced-edition).
- AW2 в строках 285/399 объявляет mesh shaders безальтернативным требованием, но строка 395 уже знает о fallback-патче. Remedy 06.03.2024 официально снизила минимум до GTX 1070/RX 5600 XT благодаря оптимизации GPU без mesh shaders. [Патчноуты Remedy](https://www.alanwake.com/story/alan-wake-2-update-notes/).
- «RTX 10 серии» (строка 282) смешивает наименование GTX и RTX; это непригодная идентификация семейства GPU.

**Неподтверждённые/спорные данные:** AppID 1080940 для AW2 требует исправления после проверки официального идентификатора; открытие соответствующей Steam-страницы в этой проверке не удалось, поэтому её содержимое не выдаётся за подтверждённое. Обязательная поддержка Steam «через год», стоимость fallback всегда 8–12 FPS и слово Vulkan в едином Enhanced-PC-паспорте также не получили здесь первичного подтверждения. Полностью RT-освещение не означает отсутствие любой растеризации всего кадра.

**Значение для проекта.** Эти примеры показывают, почему совместимость, индекс производительности и требуемый режим должны проверяться отдельно. Включение любых карточек как одного hardware calibration point закрепит D05/D27/D30. `hardware_raytraced_gi`, `variable_rate_shading`, `temporal_upscaling`, `virtual_geometry_clusters` нельзя назначать как взаимозаменяемые теги.

## Партия 11 — Cyberpunk, Overwatch, Minecraft, CS, Arma

**Полезная часть.** Лучше остальных обозначено развитие по патчам. Особенно полезно различие average FPS, низких FPS и frametime spikes в Arma; CPU render, игровой тик и сетевой snapshot здесь имеют разные причины.

**Подтверждённые результаты:**

- Cyberpunk «path tracing только с FG» (строка 37) слишком категоричен. CDPR в патче 1.62 рекомендовала также RTX 3090 для 1080p/30. Это не опровергает высокую цену 60 FPS, но опровергает обязательность FG для самого режима. [CDPR, патч 1.62](https://www.cyberpunk.net/en/news/47875/patch-1-62-ray-tracing-overdrive-mode).
- Arma 2.20 действительно обновила job system с использованием Enfusion graph; разработчик отдельно пишет, что многопоточность существовала со времён Arma 2. Главный эффект — меньше скачков и выше минимальные FPS; среднее выросло мало, максимальное иногда даже ниже. Отказ от дальнейшей поддержки x86 не означает, что 2.20 уже не имела x86-ветки. [Bohemia, OPREP 17.06.2025](https://dev.arma3.com/post/oprep-performance-optimizations-in-220).
- Minecraft Java 21 указан как переход «1.21+», но обязательная Java 21 появилась уже в **1.20.5**. [Mojang, release notes 1.20.5](https://www.minecraft.net/nl-nl/article/minecraft-java-edition-1-20-5).
- Поле «Java 1.20+» не годится как бессрочный профиль: Mojang 21.07.2026 отдельно обновила требования с целями/пресетами. Исторические 4 GB и неопределённый Core i3 нельзя выдавать за текущий минимум всех версий 1.20+. [Mojang, обновление требований](https://www.minecraft.net/en-us/article/minecraft-java-edition-system-requirements).

**Не подтверждено:** −30% latency для всего OW2, точная причинность перехода 5v5, kernel-античит как обязательная характеристика движка, постоянные 90% CPU Cyberpunk, универсальные 60 FPS на 8–12 чанках и параметры Sodium/Vulkan на уровне каждого указанного релиза. Число скачиваний мода не является верификацией его аппаратной модели.

**Значение для проекта.** Arma — подходящий проверенный источник для ограничений переноса многопоточности, но улучшение low FPS нельзя преобразовать в одинаковое снижение минимального CPU-класса. Для Minecraft важны независимые simulation/render distance, конкретная Java/GC и набор модов. Для CS input timestamp, tickrate, snapshot rate и latency не являются одной величиной.

## Связанный документ DSS-анализ-железо.md

Этот документ явно использует партии как «доказательства» влияния методов, поэтому проверен дополнительно.

- **Внутреннее противоречие знака:** `hierarchical_lod` указан в разделе снижения VRAM, хотя выше сам документ пишет +1 VRAM и действующий seed действительно имеет impact_vram=+1. Проба сохранена в inventory.json.
- **Ложная атрибуция покрытия:** карта названа «партии 1–11», но содержит Factorio, Dragon’s Dogma 2, Diablo IV, TLoU, WoW и другие игры, у которых здесь нет отдельных профилей. Возможно, они есть в иных материалах проекта; это нужно указать явно, а не считать доказанными этими 11 файлами.
- **Подмена причины:** «высокая загрузка CPU ⇒ ECS нет» и «низкий FPS ⇒ agent_update_budget=0» не следуют из наблюдения. Разные реализации могут давать одинаковый симптом; наличие/отсутствие метода требует самостоятельного источника.
- **Подмена подсистемы:** пример про объём Ultra-текстур не доказывает цену temporal_upscaling; SSAO High→Medium не доказывает цену cascaded_shadow_maps; paintmap не доказывает использование distance-field shadows; процедурное повреждение демонов не доказывает geometry cache.
- **Подмена стоимости класса сложности:** «flow field: цена не зависит от числа агентов» может относиться только к части вычисления поля при фиксированной сетке. Без выделения построения поля, применения на агентах и avoidance это неверная модель полного времени.
- **Подмена полноты реализации:** совпадение чисел impact_* с seed проверяет переписывание каталога, а не правильность этих чисел. Для animation_lod_budget seed содержит −2 CPU, тогда как документ пишет неопределённое «настр.».
- **Смешение доказательств:** верификационная таблица использует «знания модели», прежний аудит, публикации СМИ и разработчика в сходном статусе. Формат следует сохранять как заметки, а не считать каждую зелёную строку независимым измерением.

## Что полезно сохранить для будущего, а что мешает цели сейчас

Достоинство партий — широкий набор компромиссов: память вместо вычислений, preprocessing вместо runtime, качество вместо скорости, совместимость вместо новых возможностей, сетевой трафик вместо CPU. Текст может сделать рекомендации понятнее и содержательнее после проверки.

Недостаток — отсутствие наблюдаемой связи между решением и измеренным эффектом. Запись «API X, CPU Y, 60 FPS» ещё не показывает, какую часть результата вызвал API, а какую — сцена, драйвер, код или настройки. Десять пересказов одного числа не создают десять независимых калибровочных случаев.

Для будущей применимости каждого численного кейса нужны: точная версия игры/движка, платформа, сцена, preset, внутреннее/выходное разрешение, базовые/сгенерированные FPS, среднее/low/frametime, оборудование с режимом питания, источник и статус измерения. Для метода — baseline сравнения, изменяемая подсистема, условия, цена в других ресурсах, стадии offline/runtime и client/server. Это описание пробелов, **не поручение их сейчас реализовать**.

Все 11 партий оставлены без изменений. Не выполнены импорт, публикация методов, изменение коэффициентов, новые зависимости или автоматическое исправление справочников. Документы пока следует рассматривать как кандидаты на проверку и обогащение объяснений; использовать их целиком как доказательство допуска 70% по производительности нельзя.
