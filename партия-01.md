## 1. Portal (2007, Valve) — AppID 400

- **Engine:** Source (Orange Box)
- **Format:** 3D | **World:** linear | **Scale:** small
- **Platforms:** pc_windows (отдельный Steam с 2008), macOS, Linux, Shield, Switch, RTX-ремастер 2022
- **Targets:** 1080p / 60 fps
- **Object/NPC level:** low / low | **Multiplayer:** false
- **API:** DX8.1 (минимум), DX9 (рекомендованный), OpenGL (macOS/Linux); RTX-ремастер 2022 — DX12 Ultimate с path tracing через DXR/Vulkan, **минимум RTX 3060 (работает и на RTX 2060)**, эксклюзив DLSS 3 Frame Generation только на RTX 40xx

### Features
- physics_simulation, post_processing

### Инженерные решения

| Метод | Реализация | Цена |
|---|---|---|
| runtime_stencil_portal_rendering | stencil-буфер DX9 вырезает произвольную форму портала, текстурные координаты и векторы передаются через границу с коррекцией перспективы | Конфликт с водой и reflection (выключают stencil) |
| portal_momentum_conservation | импульс сохраняется через математическое преобразование векторов на границе портала | Точность зависит от float-точности углов |
| audio_propagation_through_portals | звук трассируется через оба портала с собственной аудио-геометрией | Нагрузка на CPU растёт линейно с числом открытых порталов |
| baked_occlusion_culling (BSP) | статическая видимость, предвычисленная на этапе компиляции карты | Невозможна динамическая деформация стен |
| fixed_timestep_physics | детерминированный шаг симуляции | Однопоточный скриптовый движок Source |
| depth_prepass_early_z | ранний Z-проход для снижения overdraw при множественных порталах | Дополнительный draw pass |

### Инженерный паспорт

- **Min HW:** 1.7 GHz CPU, 512 MB RAM, GPU с поддержкой SSE (DX8.1 совместимая)
- **Rec HW:** Pentium 4 3.0 GHz, 1 GB RAM, DX9 GPU
- **Frame budget:** 16.6 мс (60 fps), stencil + portal = основная статья fillrate
- **Streaming/IO:** практически нет (уровни загружаются целиком, маленькие камеры)
- **Engine limits:** **r_portaldepth = 2 (жёсткий лимит рекурсии порталов)** — каждый следующий уровень вложенности требует отдельного внеэкранного прохода рендеринга геометрии в stencil-буфер → лавинообразный рост draw calls. Лимиты BSP (Source): MAX_MAP_ENTITIES = 2048, MAX_MAP_PLANES = 65536, visclusters (жёсткий лимит)
- **API Strategy:** в Linux/Steam Deck-сборках нативная трансляция DXVK (DX9 → Vulkan) снижает CPU-overhead и улучшает совместимость с Proton
- **Mod support:** Source SDK включён (Portal: The Flash Version, Portal: Prelude, Aperture Tag)
- **Antipiracy:** нет на момент релиза, добавлен Steamworks позднее

### Баланс решений
- **Выгода:** бесшовные порталы, импульс сохраняется без отдельного кэша анимаций, звук идёт через портал.
- **Цена:** stencil-буфер ограничивает рекурсию и конфликтует с водой; короткие камеры — единственный способ держать сложность в бюджете.

### Инженерно значимые патчи (ПК)
- 2010 — унификация бинарников с Mac OS X.
- 2013 — переход на SteamPipe + Linux-экспериментальный билд.
- 2022 — Portal with RTX: перевод рендера на path tracing через RTX Remix. Требует RTX 40-й серии и DX12 Ultimate. Пересборка сцены, не косметика.

### Источник
- Valve Developer Community: developer.valvesoftware.com/wiki/Portal
- Chet Faliszek, GDC 2008 (postmortem)
- verified_by: dev_blog

## 2. Portal 2 (2011, Valve) — AppID 620

- **Engine:** Source (Left 4 Dead branch, основан на Source 2007 / Orange Box)
- **Format:** 3D | **World:** linear | **Scale:** medium
- **Platforms:** pc_windows, macOS (параллельный релиз), PS3, Linux beta 2014
- **Targets:** 1080p / 60 fps
- **Object/NPC level:** medium / low | **Multiplayer:** true (2 кооп)
- **API:** DX9, OpenGL (macOS/Linux), Source L4D branch без DX11. Source 2007/Orange Box ввёл многопоточность (physics, animation, scene traversal), не Portal 2 отдельная ветка — это та же L4D branch.

### Features
- physics_simulation, post_processing, multiplayer_netcode

### Инженерные решения

| Метод | Реализация | Цена |
|---|---|---|
| paintmap_gel_rendering | SDF-сетки (signed distance fields) для физики и рендера гелей; paintmap удваивает lightmap-память | Удвоенная VRAM на лайтмапы; слабые GPU страдают от fill-rate |
| gpu_particle_simulation | particle-pool для гелей и bubbles в pixel shader с early clip | Однопоточный submit в Source MP |
| laser_dynamic_reflection | динамическая трассировка отражений на CPU до 10 переотражений за кадр | Растёт нагрузка CPU при сложных сценах |
| excursion_funnel_force_field | инвертированные зоны гравитации как force-field volumes | Требует пересчёта коллизий каждый кадр |
| deferred_forward_plus_choice | гибридный forward+ рендеринг, выбор по сцене | Сложнее дебага |
| audio_convolution_reverb | convolution reverb на основе импульсных характеристик комнат | Высокое потребление CPU в больших зонах |
| particle_pooling | пул для дыма, искр, воды (от Left 4 Dead) | Фиксированный пул |
| lightmap_atlas_baking | единый lightmap-атлас для всех комнат | Удвоенный размер при paintmap |

### Инженерный паспорт

- **Min HW:** Core 2 Duo 2.0 GHz, 2 GB RAM, DX9 GPU 256 MB
- **Rec HW:** Quad-core CPU, 4 GB RAM, GPU 512 MB
- **Frame budget:** 16.6 мс; гели и лазеры добавляют ~1-2 мс в больших сценах
- **Streaming/IO:** нет полноценного стриминга (модульные камеры через VBSP)
- **Engine limits:** Source MP однопоточный для скриптовых сцен; лимит одновременных видимых gel-объектов в одной камере
- **Mod support:** Steam Workshop (Peer Review maps), PeTI (Paint the Intelligence) — встроенный редактор карт с paint-системой; официальный SDK
- **Antipiracy:** Steamworks (с релиза 04.2011, **нативный Steamworks с PC+PS3, без GameSpy**; GameSpy закрыт 31.05.2014, никогда не использовался Portal 2). Online-кроссплатформенный кооператив уже в день релиза

### Баланс решений
- **Выгода:** гели как SDF = одна структура данных для физики и рендера; кооп-режим с разделенным физическим миром.
- **Цена:** двойная lightmap-память; однопоточный submit нагружает CPU в больших стычках.

### Инженерно значимые патчи (ПК)
- 04.2011 — релиз на нативном Steamworks (PC+PS3), кроссплатформенный кооп, без GameSpy
- 2012 — фиксы стриминга кооп-кампаний на слабых HDD
- 2014 — Linux-билд через SteamPipe
- 2024 — 20-летний юбилейный апдейт с интеграцией эпизодов HL2

### Источник
- Valve Developer Community: developer.valvesoftware.com/wiki/Portal_2
- Chet Faliszek, GDC 2012
- verified_by: dev_blog

## 3. Garry's Mod (2006, Facepunch Studios) — AppID 4000

- **Engine:** Source (через SDK)
- **Format:** 3D | **World:** sandbox | **Scale:** medium
- **Platforms:** pc_windows (с 2006), macOS (2010), Linux (2013)
- **Targets:** 1080p / 60 fps (настраивается аддонами)
- **Object/NPC level:** high / low | **Multiplayer:** true (до 32 игроков)
- **API:** DX9 (Source SDK), OpenGL (macOS/Linux)

### Features
- physics_simulation, multiplayer_netcode, post_processing

### Инженерные решения

| Метод | Реализация | Цена |
|---|---|---|
| lua_scripting_extension | Lua-VM поверх Source — пользовательская игровая логика без перекомпиляции C++ | Один плохой аддон кладёт серверный тик |
| physics_gun_constraints | wire-constraints (верelet/weld/nocollide/freeze) для манипуляции объектами | Лимиты sbox_max; нужен cleanup |
| single_thread_main_loop | net + phys + Lua в одном потоке | Один поток = упор в clock, не в cores |
| physics_lod_sleeping | sleep/wake объектов вне зоны активности | Сложнее профилировать |
| particle_pooling | пул частиц для explosions/эффектов | Фиксированный пул |
| headless_dedicated_server | выделенный сервер без рендера | Требует отдельного бинарника |
| tick_hook_timer_replacement | замена тяжёлых tick-хуков на таймеры | Не все события можно вынести из тика |
| find_in_sphere_hot_path_avoid | FindInSphere нельзя вызывать в горячем пути | Дисциплина программирования аддонов |
| wiremod_visual_programming | визуальное программирование конструкций через wire/E2 | Ограничение на кап констрейнтов |

### Инженерный паспорт

- **Min HW:** 2 GHz, 1 GB RAM, GPU с поддержкой SSE2
- **Rec HW:** Quad-core CPU, 4 GB RAM, выделенный GPU
- **Frame budget:** зависит от аддонов; без Wiremod = близко к Source baseline
- **Streaming/IO:** минимальный; уровни Source-игр стримятся через Source VBSP
- **Engine limits:** single-thread главный цикл; лимиты sbox_max; cap констрейнтов Wiremod
- **Mod support:** Workshop (с v13), Lua API для аддонов, модели и ассеты загружаются динамически
- **Antipiracy:** Steamworks + Workshop-интеграция

### Баланс решений
- **Выгода:** мгновенное создание игр и режимов без C++ (TTT, Prop Hunt, DarkRP, Wiremod); UGC-платформа 15+ лет.
- **Цена:** однопоточный главный цикл; 64-bit и Lua-профайлеры закрыли главные затыки хостинга только спустя годы.

### Инженерно значимые патчи (ПК)
- v10 (2006) — первый Steam-релиз.
- v12 — Toybox (встроенный браузер аддонов).
- v13 — миграция на Steam Workshop, удаление Toybox.
- 2012 — поддержка Kinect (отдельный SDK).
- 2013 — SteamPipe + экспериментальный Linux-клиент.
- 2014 — 64-бит Windows.
- 2025 — интеграция ресурсов CS:S и HL2 Episodes.

### Источник
- Facepunch Studios / Solace Servers Wiki
- verified_by: dev_blog

## 4. Call of Duty 4: Modern Warfare (2007, Infinity Ward) — AppID 7940

- **Engine:** IW Engine 3.0 (собственный Infinity Ward; не публикуется как SDK)
- **Format:** 3D | **World:** linear + multiplayer (арена) | **Scale:** medium
- **Platforms:** pc_windows (DX9), macOS (Aspyr, 2008), Wii (Treyarch, Reflex Edition, 2009)
- **Targets:** 1080p / 60 fps (жёсткий таргет)
- **Object/NPC level:** medium / medium | **Multiplayer:** true (мультиплеер — главный контент)
- **API:** DX9; на Wii — собственный Treyarch-порт IW Engine

### Features
- multiplayer_netcode, physics_simulation, dynamic_shadows, post_processing, character_animation

### Инженерные решения

| Метод | Реализация | Цена |
|---|---|---|
| fixed_timestep_physics_60fps | жёсткий 60 fps-тайминг; бюджет кадра определяет всё остальное | Ограничение масштабов разрушаемости |
| material_bullet_penetration | каждый материал имеет проникающую способность (cover vs concealment) | Больше вариантов материала = больше памяти и CPU |
| audio_occlusion_reverb | собственная система окклюзии, унаследованная из CoD2 | Однопоточный sound-движок: перестрелки упираются в 1 ядро |
| dynamic_lighting_plus_dof | depth of field, динамические тени в реальном времени | Нагрузка на GPU растёт с числом источников света |
| animation_lod_budget | скелетная анимация с упрощением на дистанции | Видимые «pops» при переключении LOD |
| multiplayer_progression_unlock | XP-система, prestige, create-a-class — серверная логика | Сервер хранит состояние всех игроков |
| killstreak_server_logic | ачивки на N фрагов без смерти (3/5/7) | Серверная логика раз в кадр |
| perk_system_categorization | перки в 3 категории (по 1 из каждой) | Балансировка комбинаций — отдельная задача |

### Инженерный паспорт

- **Min HW:** Pentium 4 2.4 GHz / Athlon 64 2800+, 512 MB RAM, GeForce 6600 / Radeon X1600
- **Rec HW:** Core 2 Duo, 1 GB RAM, GeForce 7900 / Radeon X1900
- **Frame budget:** 16.6 мс; рендер + AI + сеть на одном ядре (многопоточность ограничена)
- **Streaming/IO:** нет открытого мира; уровни загружаются целиком (1–2 сек)
- **Engine limits:** IW 3.0 не имеет полноценного многопоточного сабмита; ПК-версия изначально страдала на многоядерных CPU
- **Mod support:** нет официального SDK (в отличие от Source); моддинг через внешние инструменты
- **Antipiracy:** защита через активацию по ключу; позднее Steamworks + Call of Duty 4 Modern Warfare использует Steam Cloud

### Баланс решений
- **Выгода:** 60 fps как стабильная планка, динамическое пробитие материалов даёт тактическую глубину.
- **Цена:** движок привязан к консольным ограничениям 2007 года; однопоточный sound.

### Инженерно значимые патчи (ПК)
- 2008 — Variety Map Pack через сделку с NVIDIA.
- 2016 (Remastered, Raven Software) — фиксы багов порта с кодовой базы 2007.

## 5. Sid Meier's Civilization V (2010, Firaxis Games) — AppID 8930

- **Engine:** LORE (Low Overhead Rendering Engine, собственный Firaxis)
- **Format:** 3D | **World:** hub (карта мира) | **Scale:** very_large
- **Platforms:** pc_windows (DX9/DX11), macOS (OpenGL, 2010), Linux/SteamOS (2014)
- **Targets:** 1080p / 60 fps (зависит от размера карты)
- **Object/NPC level:** high / high | **Multiplayer:** true (до 6)
- **API:** DX11 нативно с ремаппингом на DX9; OpenGL на Mac/Linux

### Features
- ai_pathfinding, procedural_generation, post_processing, multiplayer_netcode

### Инженерные решения

| Метод | Реализация | Цена |
|---|---|---|
| hex_grid_pathfinding | гексагональная сетка мира вместо квадратной | Переделка всех AI-решений, карт и интерфейса |
| hardware_tessellation_terrain | DX11 tessellation для ландшафта | Требует DX11 GPU |
| gpu_raytraced_shadows | тени через ray-tracing на GPU + AA shadow maps | Не масштабируется на старых GPU |
| one_unit_per_tile_combat | 1UPT — один юнит на гекс | Поздние эпохи теряют глубину из-за нехватки места |
| ai_four_layer_hierarchy | tactical/operational/strategic/grand-strategic AI | 4 параллельных AI-цикла = нагрузка на CPU |
| ai_flavor_personality_matrix | 26 «flavor»-параметров (1–10) на каждого лидера | Признано: AI рандомен между стратегиями |
| deferred_cpu_threading | 4 уровня AI на отдельных потоках | Синхронизация между слоями |
| time_sliced_pathfinding | pathfinding по тайлам, разнесённый по тикам | Юниты в дальних гексах могут «лагать» |
| community_moddable_dll | исходный код DLL выпущен в Fall Patch 2012 | Требует обратной совместимости |
| procedural_resource_generation | многооктавный шум Перлина для ресурсов/рельефа | Зависимость от seed-детерминизма |
| voice_acting_native_languages | лидеры говорят на родных языках (Latin, Nahuatl) | Удорожание локализации |

### Инженерный паспорт

- **Min HW:** Core 2 Duo 1.8 GHz / Athlon X2 2.0 GHz, 2 GB RAM, DX9 GPU 256 MB
- **Rec HW:** Quad-core 2.4 GHz, 4 GB RAM, DX11 GPU 1 GB
- **Frame budget:** 16.6 мс; AI на поздних ходах занимает больше всего
- **Streaming/IO:** нет полноценного стриминга (цельная карта мира); поворот камеры может требовать recompute ландшафта
- **Engine limits:** LORE оптимизирован под CPU-нагрузку AI; DX11-путь обязателен для tessellation
- **Mod support:** открытый DLL (Fall Patch 2012) — прецедент для AAA; комьюнити Vox Populi, CPP; Steam Workshop для модов
- **Antipiracy:** Steamworks + DRM 2K Games (некоторые регионы)

### Баланс решений
- **Выгода:** гекс-сетка устранила 8-направленные «шахматные» искажения; открытый DLL позволил комьюнити переписать AI.
- **Цена:** 1UPT обнулил стековые доктрины поздней игры; AI часто рандомен в выборе стратегий.

### Инженерно значимые патчи (ПК)
- 1.0.1.332 (2011) — удалена механика неизвестной технологии за каждые N ходов, ребаланс research agreement.
- Fall Patch 2012 — открыт исходный код DLL.
- Регулярные патчи 2010–2012 — краши, баланс, AI-фиксы.
- 2014 — Linux/SteamOS-порт.

### Источник
- Game Developer Magazine: «Sid Meier's Civilization V Postmortem», март 2011
- Jon Shafer: «Revisiting the Design of Civ 5», февраль 2013
- GDC 2011 LORE презентация
- verified_by: gdc_talk / postmortem

## 7. The Witcher 2: Assassins of Kings Enhanced Edition (2011/2012, CD PROJEKT RED) — AppID 20920

## Предложения по расширению DSS-каталога

Эти поля не существуют в `game_examples.json`/`source.json`, но полезны DSS:

1. **`api_versions`** — список API/RHI (DX9/DX11/DX12/Vulkan/OpenGL/Metal). Полезно для: фильтра «этот метод требует DX12» уже есть в `methods_data.py`, но привязка к примеру игры даёт контекст.
2. **`antipiracy`** — тип защиты. Полезно для: оценки рисков DRM-апдейтов (аналог GTA IV в шаблоне).
3. **`streaming_io_profile`** — тип загрузки мира. Полезно для: объяснения, почему open-world стриминг обязателен.
4. **`engine_limits`** — лимиты движка. Полезно для: предупреждений в карточке метода.
5. **`mod_support`** — открытость SDK. Полезно для: UGC-проектов (UGC — отдельная игровая функция).
6. **`frame_budget_ms`** — целевой бюджет кадра. Полезно для: калибровки hardware-оценки (текущий каталог хранит только `target_fps`).
7. **`antipiracy_impact_perf`** — отдельное поле для анти-пираток, снижающих производительность (как в шаблоне про GTA IV и GFWL).

Рекомендую: расширить схему `GameExample` этими полями **опционально** (чтобы старые записи не ломались), затем заполнить для новых партий.
