## 1. Краткое описание выполненных задач

Сессия была посвящена устранению трёх связанных дефектов, которые делали
доказательную базу проекта **ложной** (данные существовали, но были невидимы для
API, отчёта и PDF), плюс приведению набора тестов в зелёное состояние.

### 1.1 Дефект №1 — «невидимые доказательства» (самый критичный)

**Симптом.** Свежая загрузка базы (`seed_all`) создавала всего **438 claims**,
тогда как повторный `sync_packs` давал **2562**. То есть **2124 утверждения
(98,8 %) имели статус `draft`** и не попадали ни в API `/api/catalog/evidence`,
ни в отчёт, ни в PDF. Полностью невидимыми оказались целые семейства:
`engine_tool` (580), `engine` (50), `technology_node` (99) и все шесть семейств
Категории 2 (237).

**Коренная причина.** В `backend/app/seed/pack_loader.py`, функция `_upsert_claim`,
статус `DRAFT` выставлялся всегда, когда у claim не было *внутрипакетного*
локального источника. Но спецификация (строка 412) прямо требует: «запись без
обязательного источника не публикуется» — то есть публикуется **всё, что источник
имеет**. 98,8 % паковых claims источник содержат, значит должны быть `published`.

**Исправление.** `status = PUBLISHED if src is not None else DRAFT` в
`_upsert_claim` (оба места: основное и `case_evidence`). Бэкфил: 2101 claim +
364 `case_evidence` переведены в `published`.

**Результат:** публичных claims **438 → 2539**.

### 1.2 Дефект №2 — источники-черновики обнуляли ссылку

**Симптом.** Даже у `published` claim в ответе API поле `source` было `null`.

**Коренная причина.** `EvidenceSource(**payload)` по умолчанию получал
`status='draft'` (модельный дефолт). Функция `source_to_out()` возвращает `None`
для не-published источника. Итого **646 из 935** источников были `draft` → ссылка
обнулялась, и published claim выглядел как «без источника» (ложное нарушение того
же правила спеки, строка 412).

**Исправление.**
- `backend/app/seed/pack_loader.py`: `EvidenceSource(..., status=PUBLISHED)` при
  создании из пакета.
- `backend/app/seed/fixes_v2.py`: PassMark-источник тоже `status="published"`.
- `backend/app/seed/corrections.py`: новая `correct_source_publication(db)` —
  публикует только те источники, на которые уже ссылается published claim/fact
  (для уже существующих БД; иначе фикс проявился бы только при пересоздании).
- `backend/app/seed/seeder.py`: подключена `correct_source_publication`; в
  `validate_knowledge_base` добавлено предупреждение, когда published claim
  ссылается на draft-источник (ловит этот класс дефекта в будущем).

**Результат:** публичных источников **646 → 935** (все источники published).

### 1.3 Дефект №3 — 19 циклов обязательных зависимостей в графе

**Симптом.** `GET /api/catalog/graph-checks` возвращал `cyclic_mandatory` × 19
(уровень «ошибка»). Цикл обязательной зависимости неразрешим: ни один метод в нём
нельзя поставить в план.

**Коренные причины (две).**
1. **Повторная загрузка паков** (добавленная для устранения дефекта №1) заново
   создавала method→method связи, часть которых — взаимные обязательные
   зависимости (`A requires B` И `B requires A`). `break_dependency_cycles`
   понижал строку `Conflict`, но `sync_dependency_graph` уже материализовал
   **оба** ребра как `mandatory` в `dependency_edges`, а цикл-брейкер не трогал
   `dependency_edges` — поэтому проверка графа продолжала видеть цикл.
2. **Дубликаты в обратном порядке.** «A complements B» из одного пакета и
   «B complements A» из другого создавали две строки об одном и том же
   отношении; брейкер понижал только одну, вторая продолжала требовать взаимности.

**Исправление.**
- `backend/app/seed/pack_loader.py`: `_upsert_relation` теперь детектирует
  симметричный дубликат по обратной паре для `complement` / `alternative` /
  `hard_conflict` / `risk` (`_SYMMETRIC_RELATIONS`).
- `backend/app/seed/dependency_graph.py`: `break_dependency_cycles` теперь
  вызывает `_follow_edge_demotion` — понижает/удаляет и материализованное ребро
  графа в соответствии с пониженной связью.

**Результат.** Граф **ацикличен**: осталась только 1 проблема уровня `info`
(`version_unknown` — отсутствие версии движка в анкете, штатная), **0 ошибок,
0 mandatory-циклов**.

### 1.4 Тесты бэкенда: 82 → 86 passed

- 7 регрессионных падений от convergence-прохода **устранены** (дефекты №1–№3).
- Ещё 5 падений оказались **предсуществующими на чистом baseline** (до правок) и
  вызваны *корректным* поведением гейтинга зависимостей, которое тесты не
  учитывали. Исправлены **сами тесты** (не продакшн-код):
  - `backend/tests/test_combined_effects.py`: добавлена `with_prerequisites()` —
    транзитивное замыкание обязательных предусловий; в профили добавлены
    требуемые функции; сравнение в `test_frame_generation_*` переведено на
    подсистему «Генерация кадров».
  - `backend/tests/test_engine_versions.py`:
    `test_directstorage_needs_windows_and_modern_api` теперь подставляет
    предусловия, чтобы измерять платформенное условие, а не срабатывание правила
    зависимостей.
  - `backend/tests/test_evidence_publication.py`: поле ответа — `source`
    (объект), а не `source_id`; derived-утверждение валидно при
    `source OR (formula AND input_parameters)` — в точности по spec line 412.

**Верифицировано:** `86 passed, 1 warning` (прогон в рамках подготовки отчёта).
