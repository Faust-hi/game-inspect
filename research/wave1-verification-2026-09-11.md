# Волна 1: видимость игровых кейсов — отчёт о выполнении

Дата: 2026-09-11. Основание: `research/defect-diagnosis-2026-09-11-deep.md`
(дефекты N1, N7, N9). Прод-база: `backend/gamedev_dss.db`.

Волна 1 — только безопасные исправления: они **добавляют видимость** и не
меняют ни одного расчёта, поэтому числа подбора, нагрузки и расписания
остаются прежними. Правки, меняющие числа (замыкание обязательных
зависимостей), вынесены в волну 2.

## Что исправлено

**N1. Игровые кейсы не публиковались.** `pack_loader._upsert_case` создавал
`GameCase` без явного статуса, а у модели он по умолчанию `draft`. Публичный
слой (`repositories.game_cases`) фильтрует `status='published'`, поэтому в API
и отчёте были видны только 8 курируемых кейсов из 155.

**N7. Доказательство ссылалось на невидимого родителя.** 363 из 375 строк
`case_evidence` были опубликованы, но их кейс — нет. Следствие: «Сверка с
практикой» в сценарном тестировании оставалась пустой в 12 сценариях из 25,
хотя доказательство существовало.

**N9. Аудит не видел публикацию.** `tools/audit_evidence.py` читал таблицы
целиком и не сверял `status` с публичным фильтром, поэтому «полное покрытие»
и «видимая запись» были для него одним и тем же. Дефект N1 был невидим для
аудита.

## Правки в коде

| Файл | Что сделано |
| --- | --- |
| `backend/app/seed/pack_loader.py` | `_upsert_case` ставит `status` по разрешимости источника; оба вызова переносят `world_type`/`network_mode`; согласующий проход заполняет только пустое поле |
| `backend/app/seed/corrections.py` | новая функция `correct_case_publication` — публикует кейс, подтверждённый опубликованным фактом с источником; идемпотентна; вызывается из `declare_evidence_gaps` |
| `backend/app/seed/seeder.py` | `validate_knowledge_base` предупреждает, если опубликованный факт ссылается на черновой кейс |
| `tools/audit_evidence.py` | новый раздел `visibility`: по каждой таблице со столбцом `status` считает `total`/`published`/`invisible`; `evidence_claims` объявлена черновой по замыслу |
| `backend/tests/test_case_publication.py` | 12 регрессионных тестов |

Принцип, который соблюдён: кейс без подтверждённого доказательства остаётся
черновиком. Это объявленный пробел, а не повод публиковать «на всякий случай».
