# Волна 2 (часть 2): аппаратные сообщения и узкое место — отчёт о выполнении

Дата: 2026-09-11. Основание: `research/defect-diagnosis-2026-09-11-deep.md`
(дефект N8, шаг 6 плана). Прод-база: `backend/gamedev_dss.db`.

Эта часть меняет **формулировки и один диагноз**, но не схему и не данные:
**ни одной записи в базе не изменено**, поэтому бэкап базы не требуется, а
откат — только по коду (`git revert`). Числа документов перегенерированы,
потому что изменились подписи узкого места.

## Что исправлено

**1. Причина отказа противоречила сообщению.** При пустом `api_compatible`
(карты отсеял API или апскейлер) список «неподтверждённых возможностей»
вычислялся по пустому множеству карт, поэтому сообщение объявляло отсутствие
**всех** обязательных возможностей сразу — «нет GPU с поддержкой Compute
Shaders» там, где настоящая причина в API. Теперь порядок обратный: сначала
проверяется API, и только там, где есть на чём проверять возможности, они
называются.

**2. Добавлен третий, ранее не названный случай.** «Каждая возможность по
отдельности подтверждена хотя бы одной картой, но ни одна карта не подтверждает
их все» — раньше такое состояние молчаливо получало сообщение про API.
Теперь оно названо своим текстом.

**3. Недостижимая ветка.** Сообщение «в каталоге нет карты с подтверждённой
аппаратной трассировкой лучей» висело на условии
`required_rt and not any(_supports_ray_tracing(g) for g in compatible_gpus)`,
которое ложно всегда: `_pick_gpu` сам отсеивает карты без трассировки и
возвращает признак отказа. Пользователь этого сообщения не видел никогда.
Причина отказа теперь приходит из `_pick_gpu`, и ветка стала достижимой.

**4. Узкое место противоречило индексу.** Модель стоимости кадра **складывает**
растеризацию и трассировку (`combined["gpu_index"] = raster + rt`,
`gpu_raster_ms + gpu_rt_ms`), а `_bottleneck` сравнивал их **порознь**. При
raster = RT = 0.4 и CPU = 0.5 узким местом назывался CPU, хотя ограничитель —
GPU (0.8), и диагноз расходился с тем, по какому индексу подбирается видеокарта.
Теперь GPU сравнивается суммой.

## Правки в коде

| Файл | Что сделано |
| --- | --- |
| `backend/app/services/hardware.py` | `unmet`: сначала «отсеяно по API», затем «отсеяно по возможности», затем «нет карты, покрывающей все возможности сразу» |
| `backend/app/services/hardware.py` | `_pick_gpu` возвращает `tuple[HardwareGPU \| None, str \| None]` — причину отказа (`"rt"` / `"vram"` / `"perf"`) вместо флага «дело в RT?»; вызывающий называет настоящую причину |
| `backend/app/services/hardware.py` | `_bottleneck` сравнивает GPU суммой raster + RT; убран неиспользуемый параметр `model` |
| `backend/app/services/hardware.py` | `BOTTLENECK_TITLES`: ключи `gpu_raster` / `gpu_rt` заменены одним `gpu` («GPU (растеризация и трассировка суммарно)»); удалён неиспользуемый словарь `BOTTLENECK_LABELS` (мёртвый дубль подписей) |
| `backend/tests/test_hardware_messages.py` | **новый файл**, 11 тестов: сумма raster + RT; отсутствие раздельных ключей; ответ API называет стадию из модели; три причины отказа `_pick_gpu`; три ветки сообщений `unmet` (по API, по возможности, «ни одна карта не покрывает всё») |

Сообщения проверяются на уровне API с подменой `_supports_profile_gpu` и
`_gpu_feature_support`: причина и текст проверяются вместе, поэтому разойтись
снова они не смогут.

## Что изменилось в числах

Узкое место изменилось у **7 из 25** сценариев:

| Сценарий | Было | Стало | Причина |
| --- | --- | --- | --- |
| S06 Unreal Engine City Sample | GPU (растеризация) | GPU (суммарно) | та же стадия, изменилась только подпись |
| S09 DOOM Eternal | GPU (растеризация) | GPU (суммарно) | подпись |
| S12 Microsoft Flight Simulator | GPU (растеризация) | GPU (суммарно) | подпись |
| S17 Alan Wake 2 | GPU (растеризация) | GPU (суммарно) | подпись |
| S22 Hunt: Showdown | GPU (растеризация) | GPU (суммарно) | подпись |
| S10 Cyberpunk 2077 | Память | GPU (суммарно) | сумма raster + RT превысила простой подкачки |
| S13 Teardown | CPU (главный поток) | GPU (суммарно) | то же; трассировка пути в этой игре и есть ограничитель |

У S10 и S13 изменился **вывод**, а не подпись: обе величины — доли одного
бюджета кадра (индекс GPU — `(raster_ms + rt_ms) / budget`, давление памяти —
`stall_ms / budget`), поэтому сравнимы, и раньше сравнение шло с половиной
стадии. Для S13 (Teardown — трассировка пути) вывод «ограничивает GPU» также
совпадает с известным поведением игры; для S10 оба ограничителя близки, и
сообщение о памяти осталось в оговорках, если дефицит есть.

Прочие различия прогона — только `.meta.calculated_at` (время расчёта).

## Наблюдения (не дефекты этой правки)

* **Каскад неприменимой зависимости.** При проверке сообщений обнаружено:
  `variable_rate_shading` выбрасывается из расчёта, потому что его обязательная
  зависимость `deferred_forward_plus_choice` неприменима (требует функции
  `dynamic_lighting`, не выбранной в профиле). Это не молчаливая потеря —
  причина названа в `notes`, — но это тот же класс, что открытый пункт E1:
  выбрасывание метода вместе с зависимостью. Пока не исправлено.
* **Шум перегенерации аудита.** `tools/audit_evidence.py` пишет JSON без
  сортировки ключей и с абсолютным путём к базе, поэтому каждый прогон даёт
  расхождение в порядке ключей и в поле `db` при неизменных числах. Файл
  возвращён к состоянию HEAD, чтобы не тащить посторонние различия в коммит.
  Стоит зафиксировать детерминированный вывод отдельной правкой.
