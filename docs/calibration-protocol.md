# Проверка проектной оценки на внешних примерах

Статус: протокол; достижение целевого порога ещё не подтверждено.

Игровые карточки и результаты сторонних тестов — внешний проверочный набор.
Они не должны импортироваться в рабочую базу или становиться условиями формул.
Приложение получает только явно заданную анкету и выбранные методы. Неизвестные
числа объектов, устройство кода и интенсивность подсистем нельзя додумывать.

Для каждого внешнего случая сохраняются идентификатор, версия игры, источник
и дата проверки, исходные параметры, корзина, невыразимые параметры и результат
с версиями алгоритма и каталога. Используется отдельная временная база.

Сравнение оборудования допустимо только при совпадении разрешения, пресета,
целевого FPS, RT, режима апскейлинга и генерации кадров. Рекомендуемые требования
без указания режима и минимальные требования служат предупреждением, а не
измерением точности. Пользовательские замеры отделяются от требований издателя
и оценочных данных сайта. Общая требовательность игры по шкале сайта не является
эквивалентом класса CPU/GPU проекта.

Основная цель — относительная ошибка требуемой производительности CPU и GPU
не более ±70% по каждому компоненту одновременно:

`ошибка = |Pпрогноз − Pэталон| / Pэталон`.

Шкала эталона обязана происходить из сопоставимых измерений, независимых от
настраиваемых коэффициентов. Процент по произвольному индексу каталога
реальной игровой ошибкой не называется. Совместимость и память проверяются
отдельно и процентным допуском не компенсируются. Обязательная доля успешных
случаев не устанавливается: публикуются ошибки, доля попаданий, покрытие и
изменение относительно исходной версии. Дополнительно публикуются медиана,
P90, направление смещения, ширина диапазонов, число пригодных/исключённых/
неоценённых сценариев с причинами и сравнение на одном и том же наборе,
чтобы сокращение покрытия не выглядело улучшением.

Существующий критерий «±1 класс» сохраняется только как регрессия
классовых ориентиров (см. `backend/tests/test_class_regression.py`): он не
доказывает выполнение цели ±70% и не используется для настройки
коэффициентов. Точное совпадение классов, среднее абсолютное отклонение по
каждому компоненту и направление смещения публикуются рядом, но не вместо
процентной проверки.
Среднее считается сначала внутри каждой игры, затем по играм, чтобы множество
режимов одной игры не перевешивало остальные. Превышение каталога — отдельный
неуспешный исход, а не совпадение с последним классом. Случаи без достаточного
эталона не входят в числитель; их число и причины исключения обязательно видны.

Для всего внешнего набора сохраняется матрица режимов: 720p/low/30,
1080p/medium/30, 1080p/high/60, 1440p/high/60, 1080p/ultra/120, 4k/ultra/60.
Отсутствие внешнего эталона для режима не мешает проверить внутренние инварианты,
но не позволяет включать такой результат в показатель совпадения оборудования.

Плюсы, минусы и ограничения проверяются по отдельным утверждениям: выбранное
решение, условие применимости, затронутая подсистема, ожидаемое последствие,
источник и границы достоверности. Заполненность текстовых полей не означает
истинность. Отдельно фиксируются ложные утверждения, пропущенные ограничения,
неподтверждённые зависимости и случаи, которые анкета не способна выразить.
Совместимость двух методов не означает гарантированный дополнительный выигрыш.

После настройки модели набор для окончательной проверки фиксируется отдельно
от использованных для настройки случаев. Порог не достигается изменением
допуска, исключением неудобных игр или добавлением поправок по названию игры.
